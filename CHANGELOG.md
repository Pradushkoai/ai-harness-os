Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). История отдельных пакетов — в их собственных CHANGELOG.

## [0.11.0] — 2026-10-02

### Added
- **harness-loop 0.7.0 — исполнительный оракул L1 (дорожная карта 2.1, фаза A):** `ExecutorPort` + `OneScriptRunner` (изоляция temp-каталог/чистое окружение/таймаут), формат чеков в задачах бенчмарка (`call/expect/setup/case_fold/proc`), 54/70 задач с живыми чеками (118 проверок, ожидания захвачены прогоном эталонов на реальном движке, round-trip гейт), метрики L0/L1/L2 + `l1_coverage` во всех отчётах, README-методология бенчмарка с честными ограничениями; 3 эталона доведены до L1 (ОписаниеТипов/ТекущаяДата — валидно в 1С и OneScript). Живой оракул поймал реальные баги эталонов (переопределение builtin `ПустаяСтрока`, строки вместо `Тип()` в колонках) — L0-зелёные, L1-мёртвые.
- `scripts/gen_checks.py` в harness-loop — генератор чеков по правилу «реальность > предположений».

## [0.10.3] — 2026-10-02

### Changed
- **Дорожная карта 2.1 — самопроверка карты 2.0 (каждое числовое утверждение сверено с фактическим составом репозитория).** Главная находка: оценка исполнимого покрытия была занижена — версия 2.0 обещала «порядка 60% задач исполнимы» и порог «40 задач с чеками», тогда как пересчёт по фактическим категориям бенчмарка (70 задач) даёт 53 чисто языковые задачи (76%) + 11 условно исполнимых через драйвер-обёртку (query — нормализованное сравнение текстов запроса; tablepart — по условию задач «как таблица значений»; http-парсеры без сети); действительно неисполнимы только 6 (4 СКД + 2 сетевых HTTP). Теоретический потолок покрытия L1 — 91%, цель фазы A поднята до 55+ задач с чеками и ≥75% в сводных критериях. Прочие правки: ExecutorPort и OneScriptRunner размещены однозначно — новый модуль `executors` в harness-loop (исполнение — домен цикла и оценки, контракт bsl-verify — статика, не трогаем); исполнение сгенерированного кода — в изолированном временном каталоге с таймаутом; добавлены 2 риска (недоступность пилотного проекта EDT/XML, недоступность движка OneScript в среде прогона — у движка есть Windows/Linux-сборки, гейт со скип-маркером как с java); зафиксировано пятое правило карты — «отставание режет состав фазы, но не пороги приёмки»; в параллельные действия пользователя добавлен базовый живой прогон бенчмарка ДО старта фазы A (точка «до» для измерения дельты оракула); MCP-тулинг `eval_summary` получает лимит по умолчанию (полный прогон — явным флагом). Состав и порядок фаз A–E не изменились. Опечатки исправлены (в т.ч. латиница в «сменa»).

## [0.10.2] — 2026-10-02

### Changed
- **Дорожная карта 2.0 (переосмысление плана по итогам независимого аудита и реанализа всех исходных исследований).** Порядок работ зафиксирован в README: (1) исполнительный оракул L1 поверх OneScript — разделение метрик L0/L1/L2, честное покрытие по категориям; (2) новый пакет `harness-mcp` — stdio MCP-сервер с 5 тулингами поверх существующих портов (канал дистрибуции в Claude Code / opencode / Cline); (3) контекстный слой — `ContextProviderPort` со встроенным индексером и опциональным бэкендом code-index-mcp (исследование 09: «обязательно», было упущено в карте 1.0); (4) калибровка судьи ручной разметкой 30 задач с публикацией precision/recall; (5) real-world пилот с порогами, зафиксированными до старта. Phase 2 — только по триггерам (наблюдаемым событиям), не по календарю. Урок аудита закреплён: слой оценивается по стоимости адаптера, а не по громкости названия (MCP-промах v1.0: отложили и даровые тонкие адаптеры вместе с тяжёлым gateway-продуктом).

## [0.10.1] — 2026-10-02

### Fixed
- **7 тестов `bsl-verify` были красными на Windows** (независимый аудит, прогон на Python 3.14): POSIX-допущения в фикстурах, прод-код при этом корректен (живой прогон 10/10 это уже доказал). `test_parser`: `uri_to_path` применяет `os.path.normpath` — ожидания переведены на OS-агностичный вид (`os.path.normpath` / `os.path.isabs`). `test_runner::test_java_home`: фикстура создаёт `bin/java`, а `find_java` на Windows корректно ищет `java.exe` — фикстура приведена к тому же правилу. `test_verifier`: фикстуры строили URI как `f"file://{dir}"` — на Windows буква диска уходит в netloc и путь ломается; теперь канонический `Path.as_uri()` (ровно то, что отдаёт реальный bsl-language-server). Корректность подтверждена симуляцией Windows-семантики путей (`ntpath`) до и после фикса. На Linux — 494 юнит-теста зелёные без регрессий.
- **Линт-долг из независимого аудита:** все 13 замечаний ruff (E4,E7,E9,F) — 10 автофиксом + 3 вручную (F811 дубль `__version__` в agents-md, E741 `l` в generate, F841 неиспользуемая `started` в RLP-роутере) и все 21 строка длиннее 100 символов (правило репо «ruff-совместимый, line length 100» — теперь без исключений).

### Added
- **CI: Windows — first-class + ruff-гейт.** Новая job `test-windows` (windows-latest, Python 3.14 — платформа юзера, все 4 пакета, юнит-тесты + CLI-smoke): класс багов «тест писался под Linux» больше не может пройти незамеченным. Новая job `ruff` (`E4,E7,E9,F,E501`, line-length 100) — правило формата из AGENTS.md перестало существовать только на бумаге. Полная матрица версий Python остаётся на ubuntu (16 job), Windows — один Python на пакет (стоимость/покрытие).

## [0.9.0] — 2026-10-01

### Added

Qwen также в fallback coding/reasoning/cheap. Live smoke Qwen. 125 → 134 юнит-теста.

## [0.8.0] — 2026-10-01

### Added
- **`harness-loop` v0.5.0 — reference-aware judge (judge-протокол SWE-bench-BSL v0.4) + L2-метрики в отчётах.** В eval-прогонах судья видит эталонное решение и сравнивает **семантику** модуля-кандидата с эталоном (формулы, границы условий, off-by-one, граничные случаи, возвращаемый результат) — отдельный системный промпт `JUDGE_REFERENCE_SYSTEM_PROMPT`. Инвариант анти-читинга: эталон получает ТОЛЬКО судья, генератор — никогда (модель скопирует эталон → бенчмарк обесценится); инвариант протестирован на трёх уровнях (loop / run_eval / CLI). Отчёты eval получили L2-агрегаты: `judge_mode` (none/plain/reference), approved/vetoed, avg score, judge-поля в задачах, секция «Ревьюер (L2)» в markdown. Флаг `--no-judge-reference` — A/B со старым режимом. `LoopResult.judge` теперь хранит последний вердикт даже при вето, пережившем бюджет (score/issues отклонённых задач больше не теряются). 158 → 191 юнит-тест.
