# Changelog — harness-loop

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версионирование — [SemVer](https://semver.org/lang/ru/).

## [0.13.0] — 2026-10-05

### Added
- **Self-consistency судьи (`--judge-samples K`).** Пилот E1 поймал живую нестабильность: одна и та же пара (задача, код) получала veto 4/10 и затем 10/10 «без замечаний» — при уже работающем t=0 из task-пресетов роутера, то есть это серверный недетерминизм провайдера. `JudgeConfig.samples` запускает K независимых ревью; вердикт — большинство, при равенстве — одобрение (нестабильный судья не должен жечь итерации: верификатор остаётся авторитетом). `score` усредняется, `issues` дедуплицируются, а `samples`/`agreement` едут в `IterationLog` и JSON-отчёты — прямой материал для калибровки фазы D. CLI: `--judge-samples` в `run` и `eval`.
- **`ONESCRIPT_ENGINE_NOTE` — генератор узнаёт среду исполнения.** Когда eval запускается с готовым L1-оракулом, задачам с чеками в контекст добавляется примечание: движок — vanilla OneScript 2.2.0; `СтрРазделить` делит по каждому символу разделителя; `ДобавитьКДате`, `ПериодСтр`, `ПредставлениеПериода`, `ЧислоПрописью` отсутствуют (Symbol not found — подтверждено живыми пробами 2026-10-05); базовые функции границ периодов, `Формат`, `НСтр`, `СтрШаблон` работают как в 1С. Это знание о среде (разработчик всегда знает целевую платформу), а не утечка эталона — эталон остаётся judge-only. Отказ пилота `period-start` (L0 чист, судья 9/10, L1 провален на `ДобавитьКДате`) был бы предупреждён этим примечанием.

### Added
- **Query-задачи под L1 — покрытие достигло теоретического потолка 64/70 (91%).** Объект `Новый Запрос` в vanilla OneScript отсутствует (живая проба: «Type is not defined (Запрос)»), поэтому 5 query-задач получили чеки `query_text: true` по запасному плану роадмапа A2: экстрактор собирает из кода кандидата строковые литералы с `ВЫБРАТЬ`, вердикт — нормализованное сравнение (регистр ключевых слов, `|`-префиксы, пробельные серии) с эталонным текстом. Чисто-query задачи не запускают процесс движка (engine=`static-query`); смешанные прогоны мержат статические и исполняемые вердикты с сохранением порядка чеков; при падении движка статические результаты всё равно доходят до отчёта. Юнит-тесты: экстракция (двойные кавычки, фильтрация), нормализация, порядок мержа, отсутствие запуска процесса; интеграционный A4-гейт расширен: все 64 эталона проходят свои чеки.

### Changed
- **Политика верификатора по умолчанию игнорирует LS-ложноположительные коды** (`InvalidCharacterInFile` из нового `bsl_verify.LS_FALSE_POSITIVE_CODES`): em-dash в комментарии — ERROR для bsl-language-server при работающем рантайме (пилот E1: 3 итерации сожжены на несуществующую проблему). `--strict-verify` в `run`/`eval` возвращает сырой LS-вердикт.

## [0.12.0] — 2026-10-05

### Added
- **`eval` получил контекстный сокет `run`-а (фаза E).** `harness-loop eval --context-project <dir> [--context-budget N]` — тот же `resolve_provider()` (HARNESS_CONTEXT=builtin|mcp|none), тот же пер-таск скоринг релевантности: индексатор заполняет пустой контекст каждой задачи, явный контекст задачи приоритетнее. Раньше проектный контекст был доступен только одиночному `run` — пилот фазы E без этой проводки не исполнялся. 3 теста CLI: контекст доходит до user-промпта генератора, отсутствующий каталог — не крэш, HARNESS_CONTEXT=none — заметка в stderr.
- **Пилот E1 на реальной конфигурации УТ 11 — выполнен и опубликован (агрегаты в README).** 12 задач из XML-дампа (59 172 файла, 7 141 `.bsl`): resolved 10/12 (83,3 %), **L1 11/12 (91,7 %)** против порога ≥ 0.5, L2 10/11, итерации ≤ 3, ≈ 21K токенов на задачу. Каждый отказ классифицирован по слою: движок (`ДобавитьКДате` отсутствует в vanilla OneScript — L0+L2 слепы к рантайм-провалу), верификация (em-dash в комментарии = ERROR для bsl-language-server, движок исполняет; 3 итерации сожжены зря), судья (veto 4/10 на L1-зелёный код, повторный разбор — 10/10; материал калибровки D). Код пользовательского дампа в репо не попадает.

## [0.11.0] — 2026-10-05

### Fixed
- **BOM реальных EDT-дампов прятал первую сигнатуру модуля.** Все 7 141 `.bsl`-модуль XML-дампа УТ 11 начинаются с UTF-8 BOM; `\ufeff` не матчится `\s*` в сигнатурной регулярке — декларация, стоящая сразу за BOM, терялась (28 таких модулей). Декодинг головы переведён на `utf-8-sig`.
- **Срез головы 64 КБ вносил U+FFFD.** `decode(errors="replace")` на байтовом срезе заменял разрезанный пополам многобайтовый символ мусором (затрагивало 347 файлов дампа). Теперь `errors="ignore"` — обрезанный хвост отбрасывается: U+FFFD — 0, крэшей — 0.
- **`sig_total` терялся при пересборке `_ModuleInfo`** в `collect` (позиционное конструирование отбрасывало поле) — маркер усечения не доходил до рендера. Заменено на `dataclasses.replace`.

### Added
- **Пре-ранжирование по пути до чтения файлов (масштаб реальных конфигураций).** При 7 141 модуле лимит 500 файлов резал по алфавиту — индексер видел 7 % проекта, и релевантность не могла спасти модули за алфавитическим срезом. Теперь файлы ранжируются по совпадению слов задачи с путём ДО чтения: кап режет наименее релевантные, а не последние по алфавиту.
- **`HARNESS_CONTEXT_MAX_FILES=N`** — переменная окружения для пилотов на реальных конфигурациях (дефолт 500 остаётся защитой IO).
- **Маркеры усечения для LLM:** параметры длиннее 120 символов получают `…`; модули с числом сигнатур выше лимита 40 получают `(и ещё N сигнатур, скрыто лимитом)` — модель видит, что показано не всё.
- **Чистка параметров:** комментарии `//…` внутри списков параметров (реальный случай: `ПриВыгрузкеДанных(СтандартнаяОбработка, // HS\n Структура)`) вырезаются из tidy-строки.

### Changed
- **Пилот фазы E на реальном дампе УТ 11** (59 172 файла, 7 141 `.bsl`, 242 МБ): 93 % модулей имеют сигнатуры, 69 952 сигнатуры, 24,9 % с `Экспорт`; end-to-end на поддереве из 613 модулей — релевантный отбор и бюджет 8000 соблюдены. Цифры и таблица находок — в README (`Харднинг на реальной конфигурации`).

## [0.10.2] — 2026-10-05

### Added
- **Калибровка без расхода токенов: `prepare --from-reports`.** Кандидаты берутся из JSON-отчётов живого прогона (`harness-loop eval --save-report`) вместо повторного прогона цикла — та же выборка, ноль LLM-вызовов. Из отчётов читаются только `id` и `code`: судейские вердикты и L1-исходы не извлекаются сознательно — файл кандидатов не должен доносить решения судьи до разметчика, слепота разметки сохраняется. `--ids ID1,ID2` — прицельная выборка с сохранением порядка (работает и для живого прогона, и для отчётного пути). Поддержаны списки файлов через запятую; при дубликате задачи побеждает поздний отчёт. `calibration/` добавлен в `.gitignore` корня — человеческая разметка не коммитится.

## [0.10.1] — 2026-10-05

### Fixed
- **`func-http-url-parts`: квирк `СтрРазделить` в OneScript 2.2.0 наказывал корректный 1С-код.** Живой judge-прогон (Qwen + DeepSeek, 70 задач) поймал расхождение: кандидат с каноничной 1С-семантикой вернул порт 8080 и упал на чеке, ожидавшем 80. Расследование с байтовыми дампами: движок делит строку по **каждому символу** аргумента-разделителя, а не по подстроке (1С делит по подстроке) — `СтрРазделить("http://host:8080/path", "://", Ложь)` даёт `["http","host","8080","path"]` вместо 1С-`["http","host:8080/path"]`. Эталон был написан под квирк, чек ожидания «80» закреплял его. Эталон переписан на `СтрНайти`/`Сред` (эквивалентно и в 1С, и в OneScript), чек исправлен на 8080 + добавлены чеки на порты по умолчанию (80/443) — теперь 118 проверок. Квирк задокументирован в docstring `executors.py`; регресс-тест `test_bundled_reference_avoids_multichar_strsplit` запрещает многосимвольные разделители `СтрРазделить` во всех эталонах (аудит остальных 7 вхождений: все односимвольные — безопасны).

## [0.10.0] — 2026-10-05

### Added
- **Калибровка судьи — тулинг фазы D (дорожная карта 2.1).** `scripts/judge_calibration.py`, две стадии: `prepare` (стратифицированная по категориям/сложности выборка 30 задач с seeded-детерминизмом, прогон цикла, дамп кандидатов + шаблон разметки) и `run` (судья по reference-aware протоколу на каждом кандидате, confusion-матрица, precision/recall/F1/accuracy, вывод «OK ≥ 0.70 / ниже порога»). Версия судейского промпта фиксируется хэшем sha256-12 — метрики привязаны к промпту. Методичка слепой разметки (D1) — в docstring: кандидаты без вердиктов судьи, семантическое сравнение с эталоном, обязательная причина для fail. Цифры будут опубликованы после разметки человеком — единственной неавтоматизируемой части фазы.
- **Протокол real-world пилота (фаза E) в README:** таблица порогов со слотами «УТВЕРДИТЬ» (L1-проходимость, бюджет), зафиксированные лимит итераций и состав срезов, критерий остановки, требование классификации отказов по слоям. Пороги утверждаются до первой задачи пилота.

## [0.9.0] — 2026-10-05

### Added
- **Контекстный слой (дорожная карта 2.1, фаза C).** Порт `ContextProviderPort.collect(project_path, task, max_tokens)` в новом модуле `context.py` + два адаптера. `BuiltInIndexer` — чистый stdlib: rglob `*.bsl`/`*.os` (лимиты 500 файлов / 64 КБ на файл), сигнатуры процедур и функций (до 40 на модуль, флаг Экспорт), ссылки на метаданные 1С, ранжирование модулей по релевантности к словам задачи, жёсткий токен-бюджет (дефолт 8000) с построчной обрезкой. `McpIndexerBackend` — subprocess-клиент к внешнему code-index MCP-серверу (spawn → initialize → tools/list → tools/call, тот же stdio-JSON-RPC что и harness-mcp); любая неудача тихо откатывает на встроенный индексер, предупреждение сохраняется в `note`. Выбор адаптера — одна переменная: `HARNESS_CONTEXT=builtin|mcp|none` (+ `CODE_INDEX_MCP_PATH`, `CODE_INDEX_MCP_TOOLS`).

- **CLI:** `harness-loop run --context-project <каталог> [--context-budget N]`; `doctor` показывает выбранный бэкенд контекста и его состояние.
- **A/B-демо (C4):** `scripts/ab_context.py` — синтетическое дерево проекта из категорий бенчмарка, две руки (bare/context), сравнение L0/L1/L2; без LLM-ключей печатает дерево и образец контекста.
- harness-mcp: `run_loop` принимает `project_path` (индексация контекста прямо из агента), детали прогона показывают `context=builtin:123t`.

## [0.8.0] — 2026-10-05

### Added
- **`http_stub`-чеки: сетевые задачи под живым оракулом L1.** `ExecCheck.http_stub` — исполнитель поднимает локальный стаб-сервер (127.0.0.1, эфемерный порт) на время прогона модуля и вливает порт в драйвер переменной `ПортСервера` (единственный санкционированный способ узнать адрес). Маршруты: `/` и `/data` → 200 с фиксированным телом, `/missing` → 404, `/flaky` — обрывает первые два соединения (клиентский путь исключения), затем 200: логика повторов испытывается по-настоящему. Внешние хосты не затрагиваются. Счётчик попаданий — своя копия на каждый прогон: состояние не течёт между модулями гейта.
- **59 из 70 задач несут живые чеки (покрытие L1 = 84%, было 77%)** — 116 проверок. Добавлены: `struct-where-fields` (двухаргументный `Свойство(Имя, Значение)` ПОДДЕРЖАН движком 2.2.0 — прежняя запись о несовместимости опровергнута живой пробой), `func-parse-date-dot`, `func-nstr-parse`, `proc-http-get`, `func-http-retry-get`. Число проверок в записи 0.7.0 уточнено: фактически было 100, а не 118.
- Сплиттер `setup`-инструкций уважает кавычки (`_split_setup_statements`): `;` внутри строкового литерала больше не разрывает подготовку — формат НСтр сам разделён точками с запятой.

### Changed
- Границы неисполняемого переформулированы по результатам живых проб: 11 задач L0+L2 с причинами (`query`×5 — нет объекта Запрос; `skd`×4 — компоновка только в платформе; `struct-merge`/`struct-to-map` — семантика итерации `Структуры` в 1С (строка-ключ) и OneScript (`КлючИЗначение`) расходится, каноничное 1С-решение падает на `Базовая[Ключ]` — L1-чек был бы несправедлив к корректным решениям).

## [0.7.0] — 2026-10-02

### Added
- **Исполнительный оракул L1 (дорожная карта 2.1, фаза A).** Новый модуль `executors`: `ExecutorPort` + `OneScriptRunner` — сгенерированный модуль оборачивается драйвером и исполняется движком OneScript в изолированном temp-каталоге с чистым окружением (переменные вида API_KEY/TOKEN/SECRET не передаются дочернему процессу) и жёстким таймаутом (бесконечный цикл = проваленный чек, а не зависший харнесс). Дискавери: `OSCRIPT_PATH` → PATH → `OSCRIPT_HOME/bin`. Движка нет → L1 «не измерялся» (skip, как java у bsl LS), а не «0 из N».
- **Формат чеков в задачах** (`checks:` в YAML): `call` (BSL-выражение или вызов процедуры), `expect` (ожидаемый вывод), `setup` (подготовка нетривиальных входов — массивы/таблицы/структуры), `case_fold` (нормализованное сравнение текстов), `proc` (проверка вывода процедуры). Парсинг с валидацией как у остальных полей задачи.
- **54 из 70 задач несут живые чеки (покрытие L1 = 77%)** — 100 проверок (уточнено в 0.8.0: в ранней записи значилось 118). Ожидания захвачены прогоном эталонных решений на реальном движке (`scripts/gen_checks.py`, правило «реальность > предположений»), round-trip гейт: эталон обязан проходить собственные чеки; интеграционный тест фиксирует это на каждой машине с oscript.
- **Метрики трёх уровней в отчётах:** `resolved_l0` (синоним исторического `resolved` — история метрик не ломается), `resolved_l1`, `l1_measured`, `l1_coverage` в JSON; строка `L0 x/y | L1 a/b | L2 c/d` в summary и markdown. Уровни независимы по дизайну: дивергенция L0/L1 — сигнал, а не шум.
- **CLI:** `harness-loop eval` автоматически подхватывает оракул (флаг `--no-exec` для отключения), `doctor` показывает наличие движка; stderr-заметка, если чеки есть, а движка нет.
- **README: раздел «Методология: что измеряет бенчмарк»** — три уровня, покрытие, честный список неисполняемого (query×5, skd×4, сеть×2, 9 несовместимых эталонов) и правило публикации цифр только со ссылкой на методологию.
- 50 юнит-тестов (241 суммарно) + 4 интеграционных (маркер `integration`, скип без движка).

### Fixed
- **Задача func-is-blank-string переименована в `ЭтоПустаяСтрока`** (prompt + эталон): старое имя `ПустаяСтрока` — встроенная функция OneScript, модуль с таким определением не компилируется движком (L0-зелёный, L1-мёртвый — LS этот конфликт не помечает). id задачи стабилен.
- **Три эталона доведены до L1** (правки валидны и в 1С, и в OneScript, LS-гейт зелёный): `table-create-catalog`/`table-group-sum` — `Новый ОписаниеТипов("Число")` вместо строки `"Число"` в типах колонок; `proc-fill-structure` — `ТекущаяДата()` вместо сессионной `ТекущаяДатаСеанса()` (нет в standalone-движке).
- Генератор чеков идемпотентен: задачи с существующими чеками не трогаются при повторном прогоне.

### Changed
- Потолок покрытия L1 честно понижен с заявленных в карте 2.1 «91%» до фактических 70%: query-эталоны строят `Новый Запрос`, которого нет в ванильном OneScript; 9 эталонов используют неисполняемые паттерны (строка вместо `Тип()` в колонках, итерация `Структуры` и др.). Оставшиеся 16 — предмет следующего минорного (потолок 81%).

## [0.6.0] — 2026-10-02

### Added
- **Mini SWE-bench-BSL v0.4: 54 → 70 задач — шаг к реальным 1С-проектам** (дорожная карта,
  пункт «рост набора под реальные 1С-проекты»). Четыре новые категории по 4 задачи:
  - **nstr** — НСтр и многострочные строковые литералы: сборка/разбор интернационализированных
    строк, продолжение строк через «|»;
  - **http** — HTTPСоединение/HTTPЗапрос: коды состояний, разбор адреса, GET с таймаутом,
    повтор запроса при исключении;
  - **skd** — программная компоновка данных: параметры и отборы настроек, полный цикл
    «макет → процессор → вывод в таблицу значений», восстановление пользовательских настроек;
  - **tablepart** — табличные части через коллекции строк: перезаполнение через
    ЗаполнитьЗначенияСвойств, сумма по колонке, поиск строки, удаление пустых строк
    обратным обходом (классическая ловушка с индексацией). Проведение документов требует

## [0.5.0] — 2026-10-01

### Added
- **Reference-aware judge (L2 v2, judge-протокол SWE-bench-BSL v0.4).** В eval-прогонах судья
  теперь получает эталонное решение задачи и сравнивает **семантику** сгенерированного модуля
  с эталоном: формулы и порядок операций, границы условий (включительно/исключительно),
  off-by-one, поведение на граничных/вырожденных случаях (пустой ввод, ноль, один элемент),
  тип и структура возвращаемого результата. Для этого — отдельный системный промпт
  `JUDGE_REFERENCE_SYSTEM_PROMPT` (эталон = один из корректных вариантов, стиль ≠ дефект)
  и секция эталона в `judge_review_prompt(reference=...)`. Прежний режим остался дефолтом
  для `run` (ad-hoc задачам эталон неоткуда взяться).
- **Инвариант анти-читинга: эталон видит ТОЛЬКО судья.** `BslAgentLoop.run(reference=...)`
  прокидывает эталон в `Judge.review` и никогда — в task/fix/judge-fix промпты генератора:
  покажи эталон модели — она его скопирует, и бенчмарк обесценится. Инвариант зафиксирован
  тестами на трёх уровнях (loop / run_eval / CLI).
- **L2-агрегаты в отчётах eval.** `EvalReport.judge_mode` (none / plain / reference — что
  реально произошло), `judge_stats()` ({mode, judged, approved, vetoed, avg_score}),
  `TaskOutcome.judge_approved` / `judge_score`, секция «Ревьюер (L2)» в markdown, блок
  `judge` в JSON, judge-строка в summary. Отчёт отвечает на вопрос «насколько строг судья
  и что он завалил», а не только «сколько задач решено».
- **Флаг `eval --no-judge-reference`**: A/B-сравнение reference-aware и plain-режимов
  (plain = поведение v0.4) на одном и том же наборе задач.

### Changed
- **`LoopResult.judge` теперь хранит последний вердикт судьи, даже если вето пережило бюджет**
  (раньше при `judge_rejected` вердикт терялся, judge оставался None). Отчёты eval сохраняют
  score/issues отклонённых задач; `passed`/`failure_reason` не изменились. Обновлён
  затронутый тест.

### Тесты
- 158 → 191 юнит-тест (+33: reference-режим промптов и судьи, анти-читинг-инвариант на
  трёх уровнях, judge_mode/judge_stats в отчётах, CLI-флаг). Интеграционные: 5 (без
  изменений, реальный LS).

## [0.2.0] — 2026-10-01

### Added
- **Judge-цепь (L2, второе мнение).** `Judge` над любым LLMPort (на практике — свой `RouterPort`, чейн `--judge-chain`): смотрит задачу + сгенерированный модуль + остаточные диагностики, отвечает строгим форматом `VERDICT/SCORE/ISSUES/REASONING`. - **Телеметрия Langfuse** (`LangfuseTelemetry`): ноль зависимостей (stdlib urllib → `POST /api/public/ingestion`), два шва — `on_router_event` (события роутера: skip/retry/error/ok с usage) и `on_iteration` (итерации: токены, латентности, счётчики, judge). Ключи только по именам env (`LANGFUSE_PUBLIC_KEY/SECRET_KEY/HOST`), нет ключей — тихий no-op, сетевые ошибки проглатываются, код и промпты в пейлоады не попадают. CLI-флаг `--langfuse`, doctor показывает статус ключей.
- **Mini SWE-bench-BSL** (стратегический asset — первого публичного BSL-бенчмарка не существует): формат задач YAML (`id/category/difficulty/prompt/context/reference`), `load_tasks()` с валидацией, `run_eval()` над обычным циклом, `EvalReport` (`summary_lines/to_dict/to_markdown/save_json/save_markdown`). Встроенный набор v0: 10 задач (function/loop/branching/errors/string/structure). Reference-решения репортятся, гейтинга по ним нет (строковое сравнение кода бессмысленно). CLI `harness-loop eval` (`--tasks/--limit/--judge/--langfuse/--save-report/--markdown/--json`), exit 0 при любом pass rate.
- CLI `run`: флаги `--judge`, `--judge-chain`, `--judge-model`, `--langfuse`; verbose-прогресс показывает judge-вердикты; JSON-выдача дополнена блоками `judge`/`judge_error`/`totals.judge_ms`.
- `IterationLog`: поля `judge_verdict/judge_issues/judge_ms`; `LoopResult`: `judge`, `judge_error`, `total_judge_ms`, причина `judge_rejected`.
- 144 юнит-теста (было 63): +25 парсер/промпты judge, +10 интеграция цикл×judge, +14 телеметрия (транспорт мокается), +19 evals, +13 CLI (judge/eval/langfuse/doctor).

## [0.1.0] — 2026-09-30
